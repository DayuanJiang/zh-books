# 翻译文档的可选图解与阅读样式

仅当用户明确要求配图、概念图、SVG 或阅读样式改造时启用。纯翻译不自动加图、不迁移框架，也不改写原文来配合图解。宿主有合适的前端技能时使用其构建与浏览器验证流程；没有时也要区分已做和未做的检查。

未启用本扩展不等于免除交付校样：普通整书任务仍按 [repository-workflow.md](repository-workflow.md) 检查实际交付格式。这里额外处理展示改造。已定稿正文、原图复现、教学图解和代码语言改编分别验收；修改解释所依赖的正文或术语时，撤销受影响图解与派生页的旧通过状态，再核义和校样。

## 先验收样章，再推广

整书改造先选能覆盖正文、引用、列表、图表和注释的代表性章节，在真实阅读页校准。中文模式不能只测首屏或英文长段落：检查题辞、标题、图题、列表与表格；将译者补充与原著内容区分。格式误识别产生的裸露星号、被当成代码的引文、未译内容和失配脚注都应单列，不能靠隐藏节点掩盖。

在样章中确认阅读宽度、字号、配色、注释与随文图解位置，再推广共享样式。用户已确认的样式直接沿用；仅修一处配色或角标时，不重新要求整书验收或扩大改动。样章通过不代表其他章节通过，承诺全书覆盖时仍需逐章检查相应内容。

## 概念先于图形

- 每张图先确定一个具体的读者问题、预期答案，以及图中的哪些关系让读者推导出答案；记录对应标题、段落或原文摘录。图题、核心结论和关系必须能回到原文。
- 按概念选形式：流程、比较、依赖、时间线、反馈回路、独立维度或决策树，不给所有章节套同一种框图。
- 优先呈现可检查的例子：同一输入为何产生不同结果、一个依赖变动影响哪些节点、两个条件能否同时成立。若图形只是把提纲放进彩色框，且列表或原书图片已能表达，就不必另加图。
- 检查箭头代表的是先后、依赖还是因果；分组不等于层级，大小不等于重要性。不得编造数字、比例、排名或“唯一正确流程”。
- 明确区分原文事实与教学示例。图解应为新增讲解层，不能替换原文证据、掩盖原有缺损，或把源文推测画成确定结论。
- 多章并行时共享样式与数据契约：语义颜色、字体、命名、可访问性、元数据和输出路径；章节所有权不重叠。用户要求“每章一个 agent”时按章分配，可分批运行；否则按规模安排，不固定 agent 数量。共享阅读器和最终集成由主 agent 管理。

## 章首、章中、章末三类图的分工

同一本书里，图放在哪里决定它能讲什么。三类图各有一个任务，不互相替代，也不重复。

- **章首图是读前地图。** 读者此时一个字都没读，图里出现的每个词都必须是日常语言，本章才解释的术语不能出现。内容只有三样：本章要回答的问题、本章分哪几块以及各块怎么关联、一句话答案。全图控制在一百字左右，桌面高度不超过正文首屏的一半。把章节结论压缩成示意图放在章首是常见错误：读者看到的是复习图，却没有复习的基础。
- **章中图回答一个此刻会冒出来的具体问题。** 锚在它所解释的段落或代码示例之后，先让读者读到例子，再看图并排对照；给出具体的输入、路径、返回值或调用次数，让读者能自己推出图中每个结论。一张图只回答一个问题。
- **章末图按情节重讲本章。** 用四到五幕的叙事轨道（起点、变化、转折、做法之类按本章情节命名）加一块“这一章最想强调的”，让读者重新认识这章讲了什么故事、作者站在哪边。形式上要区别于章首图，也区别于把内容提要排成带图标的列表；篇幅可以是章首图的两到三倍。

章首图的形式要能一眼识别，又要表达各块之间的关系，所以既不能每章一种画法，也不能全部套同一种卡片排列。可行的做法是准备一小库图形形式（坐标图、插座与可替换部件、流水线、支柱、前后对比、分层、循环之类五到七种），每章按自身逻辑选一种；用图标承担含义，用形状承担关系，文字只留标签和一句十来字的说明。把目录装进带编号的方框不算可视化，用户会立刻指出来。

审校者写给自己的边界说明（“图示不代表实测成本”“空白不代表不可行”“本例不证明全部行为正确”）留在图的元数据 `limits` 字段里，不写进图的底部小字。它们增加阅读负担，也让图显得没有底气。一句里同时有实质内容和边界说明时，只保留实质那半句。

大范围重画前，先向用户说清现有图到底哪里不对，再说明打算怎么画，然后用一两章做前后对比原型放在临时目录里给用户看，获准后再推广到全书。用户看到方向不对时，纠正一两张原型远比纠正五十张成品便宜。

多章图形宜从每章一份内容数据（问题、各部分的图标与文字、幕与主张）由脚本生成，逐张手绘难以保持一致：脚本生成时字体、配色、间距全书统一，改措辞只改数据。生成器给每个文字槽位设宽度预算，超出就构建失败，不让文字溢出到页面上；章级图固定宽度、高度随内容；手机版式由同一数据竖向重排，不把桌面图缩小。图标路径连同许可说明一起存入仓库，不在构建时联网取。生成步骤接进 CI，图与数据不同步就失败。

## 逐图去留审核

审核已有图时，用 [diagram-review-template.md](diagram-review-template.md) 记录决定；复用已有元数据结构即可，不强制新增同义字段或完整审计系统。

- **保留 `keep`**：已有图能回答明确问题，说明其独有作用。
- **修改 `revise`**：表达关系基本成立，修正标签、条件、箭头或局部示例。
- **重画 `replace`**：改变解释方式，展示原图缺少的可推导关系；只换颜色或标题不算重画。
- **移出 `retire`**：冗余、误导或缺少解释增益的图退出阅读页，记录理由及正文或其他图如何承担必要信息。

不把“每章至少几张图”作为质量标准；用户明确要求数量时，说明数量与解释任务的取舍。保留修改前的可恢复版本，不顺手删除原书图片。退役决定必须落实到生成清单和阅读页，不能只写 `enabled:false` 却仍插入图。协调重建共享清单后，核实有效图和退役图集合、插入锚点与打开的图一致；记录已审核、已修改、已集成和已验证，不能相互替代。

主 agent 接收章节结果时，核对实际 SVG 差异与源文，查看可读的修改前后截图，不能把子 agent 的“通过”回复直接当作总体验收。

## 阅读配色与句末注释

以下规则在用户要求相应改造时适用。沿用既有编号、样式和无障碍约定，不自动将全部注释替换为圆点或悬浮弹层。

- 阅读配色以用户选择和现有设计为准。用户反馈纯白刺眼时，调整共享背景和语义颜色，覆盖正文、导航、代码、图解及弹层；保持文字可辨，不擅自变暗原书图片，也不把某个色值或“护眼”效果写成通用结论。
- 注释锚点应对应具体句子或词语。若用户要求句末圆点，使用低干扰的上标标记，紧贴所注句末的右上方，不让一个宽大的居中按钮看起来属于下一句。缩小可见标记不等于缩小可点击区域，悬停、展开和键盘焦点可适度强调。
- 标记应随被注文字换行，不能独占下一行或挂到下一句前。可按当前 DOM 使用不换行分组或排版连接机制；不要为定位而改写原文，连接符也不应污染复制文本、搜索或原文匹配。
- 验证短句、长句、行尾标点、连续注释和不同字号。结合真实字形边界检查上标高度与句末距离；透明点击区域不能截获相邻链接或其他注释。像素值由字体和阅读器决定，不把单次修复的宽高固化成模板。
- 注释支持桌面悬停、手机点击及键盘打开和关闭；弹层关闭后保留阅读位置，必要时恢复焦点。检查透明区域实际命中、弹层边界及窄屏换行，不仅断言弹层存在。

## SVG 与阅读器契约

- 确定性关系图适合可编辑 SVG。根据标签密度确定画布和断点，不把一次项目的尺寸固化为全局模板；必要时重排手机布局，不能只把桌面图缩小到不可读。
- SVG 应有 `viewBox`、可访问的标题与描述、作用域内样式和唯一 ID。检查嵌入两份图或打开弹窗时的 ID、marker 和 CSS 冲突。
- 区分嵌入方式：`<img src="...svg">` 在宿主图像元素上提供合适的 `alt`；inline SVG 核对实际可访问名称，可用 `aria-labelledby` 关联其标题。资源文件内部存在 `title/desc`，不证明阅读页已经正确暴露这些信息。
- 复杂图的短描述无法包含必要关系时，在邻近正文、图注或可访问详情中提供完整文字说明，包含关键关系、条件与结论；必要时用结构化列表或表格。已有正文完整解释时建立明确关联，避免重复。不要仅把图名或节点清单当作等价说明，也不要将需要结构导航的长表格只塞进 `aria-describedby`。
- 检查实际渲染的字形边界、箭头、标签和分组框；文字没有越出 `viewBox`，不代表它没有压住箭头或越出所属框。自动检测后仍需人工看图。
- 纯静态讲解 SVG 不需要脚本、事件属性或外部资源。嵌入前校验格式和引用；限制检查与资源信任边界相称，不宣称少数正则就构成通用 SVG 安全沙箱。
- 保留已有渲染框架、章节 URL、导航、搜索、图片和代码展示。正文、图解资源、阅读器样式/行为分别管理，避免靠改正文实现显示效果。
- 按需求提供放大、缩放、适应窗口、下载与键盘关闭；检查关闭后焦点恢复、读图弹窗与手机目录的层级、点击命中和滚动。
- 若增加主题、字号或阅读模式，验证持久化与失效回退；中文优先模式必须保留无中文对应的英文，不能按语言标签整体隐藏。
- 主题要覆盖内嵌 SVG、代码和链接。旧主题、插件注入样式和祖先 stacking context 可能覆盖新 CSS；实际测量位置、计算样式和点击目标，不靠不断增加 `z-index` 猜测。
- 原有评论、远端服务若改为按需加载，要保留用户调用入口并分别说明其验证情况。不要因本地核心阅读可用，就声称评论登录或外部链接全部可用。

## 浏览器验收

将静态校验、实际交互和人工视觉检查分别记账，不能用其中一个冒充另外两个。内容与解释审核也须独立于这些技术检查。

1. **静态检查**：章节覆盖、SVG XML、引用目标、唯一 ID、源文追溯、正文保护和构建/测试。
   没有现成校验器时，可按[通用脚本文档](reusable-scripts.md)使用 `svg_check.py`。
   它提示复合路径上的 marker、ID 和资源引用问题，不测字形边界、箭头是否可读或解释是否有效。
2. **渲染检查**：真实桌面与手机视口，并抽查断点附近。检查所有承诺覆盖的章节与图布局，记录缺图、空白、横向溢出、文本遮挡及主题对比。
3. **交互检查**：按实际功能走“打开章节 → 搜索/目录换章 → 读图 → 放大/关闭”，并复测原有图片缩放、锚点和翻页。检查控制台及失败请求，而非只监听未捕获异常。
4. **异步等待**：等待当前路由、图加载和弹窗可见等具体状态，避免旧章节就绪标记造成假通过；截图要等字体、图片与颜色过渡稳定。固定睡眠不替代状态断言。
5. **视觉验收**：逐图或用能读清文字的联系表检查所有新增图；对比修改前后阅读页和预先确定的设计约束。异常的几何检测候选需要人工裁定。
   图多时先跑一遍真实浏览器里的几何检查再看图：把每张 SVG 依次内联到页面，按 `viewBox` 设定尺寸，对每个 `text` 取 `getBoundingClientRect()`，报告越出画布右边或下边、两段文字矩形相交、以及文字起点在某个矩形内却越过该矩形右边的情况。字体宽度估算和浏览器实际字形有差异，这一步能在几秒内查完上百张图；设计上横跨方框边缘的标签会被误报，逐条确认后接受。
6. **信息可达性**：在实际阅读页检查可访问名称、文字说明的关联与可发现性、键盘路径和弹窗焦点；适用时检查可访问树及读屏表现。只测到名称存在，不能宣称复杂关系、读屏体验或全部无障碍要求已通过。

## 理解效果的证据边界

“内容符合原文”“图形能支撑预期答案”“页面显示正常”都不等于读者理解得更好。没有真实读者测试时，明确这是解释设计判断，不能把截图、测试数量或 agent 评语当作学习效果证据。

需要验证理解增益且用户同意时，可比较“正文”与“正文加图”的理解题正确率、耗时和错误类型，控制题目难度与重复阅读的影响，并记录样本限制。不要为一般配图任务强制开展实验或擅自招募、收集读者数据。

发现问题后重跑相同操作及受影响范围。浏览器不可用时说明确切限制与宿主允许的替代路径；没有真实截图时不得声称“视觉验收通过”。截图、临时脚本和诊断记录不混入仓库，除非项目规范或用户要求保留。跨会话任务按 [repository-workflow.md](repository-workflow.md) 保存轻量检查点。最终给出预览入口、实际测试范围与未验证的浏览器/登录流程，以及是否做过读者理解测试。
