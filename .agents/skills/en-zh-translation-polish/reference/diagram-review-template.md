# 逐图审核记录

用于已获准的技术文档配图或图解审核。按项目规模保存在现有图解元数据、表格或审核文件中；不要求每张图各建一个文件。字段只帮助记录可核对的决定，填满模板本身不代表图解合格。

| 项目 | 记录内容 |
| --- | --- |
| 图与位置 | 图 ID、所属章节、正文插入锚点、桌面／手机版本 |
| 读者问题 | 看完图后应能回答的具体问题，不只写章节主题 |
| 预期答案 | 答案及成立条件，不夸大原文结论 |
| 图形推理 | 哪些节点、箭头、排列、分支或对照使答案可推导 |
| 原文证据 | 可定位的段落或摘录；区分原著事实、推测和自拟教学示例 |
| 文字等价信息 | 关键关系、条件和结论在哪里以文字完整表达；记录宿主嵌入方式与关联，已有正文足够时不重复 |
| 图内文字 | 图里只有标签和读者需要的说明；审校边界（“图示不代表实测”“本例不证明全部”）写在本记录的 `limits`，不进图；章首图不出现本章才解释的术语 |
| 当前问题与决定 | `keep`、`revise`、`replace` 或 `retire`；说明独有作用、缺陷或冗余 |
| 实际变化与边界 | 改了哪些表达、为什么更合适、仍不能说明什么；退役后必要信息在哪里 |
| 验证状态 | 源文审核、图形修改、清单／页面集成、静态校验、浏览器交互、目视截图、信息可达性分别记录 |

仅作粒度示范：问题“返回的集合没变，为什么调用方仍失败？”可以用同一组值的两种顺序，以及“比较集合”和“读取首项”的两条判断作对照。说明新顺序与调用方代码是否为教学构造，不把它们冒充某个运行时的实测行为。

批次汇总分别统计已审核、修改、退役、已集成、已验证和待处理项，并标明未进行的真实读者测试。不设置最低图数，不把保留数量当作质量分数。
