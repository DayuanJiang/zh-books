# 整书翻译、审阅与交付

用于多文件、整章或整书任务。以下是结合翻译、出版编辑及机器辅助工作形成的操作流程，不冒充某个标准的全文，也不宣称唯一最优。单章、短文和局部修正按范围缩减；只审阅时记录发现与建议，不改正文。

## 1. 任务约定与源文验收

沿用已有项目说明，用简短任务约定明确：读者与用途、英文版本、中文地区用语、作者语气、术语及注释原则、需覆盖内容、交付格式、可用审核者、时间／预算与验收责任。用户已说清楚的不重复问；只有影响意义、范围、对外传输或交付承诺的问题才集中确认。

- 区分参考草稿、完整阅读稿、经过专业人工审校的出版稿。等级按约定需求，不按模型数量或脚本分数决定；不足时说明缺口，不静默降档或自动聘请人员。
- 在发送整书给外部服务前核对用户授权及材料使用限制；使用宿主既有能力不自动授权额外付费 API。技能许可不代表拥有输入书籍的出版或再分发权利。
- 保存原始 EPUB／PDF／其他源文件和版本信息，提取文本另存；核对正文、前后言、图题、脚注、附录、参考文献等约定范围。对照目录与源文单元检查遗漏、重复、截断、代码及公式识别错误，疑难页或图回看原载体，不能只比文件数量。
- 记录源文与译稿的实际覆盖关系。仓库中的英文可能只是节选，不能未经核对就作为整书原文；缺损保留并单列，不从中文反推英文。清理提取噪声不等于改写作者内容。
- 再看工作区差异、渲染方式和现有工具。基线包含用户尚未提交的改动，不能默认 `HEAD` 就是基线；原始译稿也保留可恢复版本。

源文覆盖、提取正确性与编辑保护是三种检查：内容没被改坏不证明提取完整。缺口影响哪些章节就明确限制哪些结论，不把未确认内容标为已通过。

## 2. 全书认识与语言资源

先建立足以支持任务的全书概览，再深入当前章节。概览记录论证主线、核心概念、定义所在位置、章节依赖与重要回指；文学按需要记录人物声音、叙述视角、时间线和反复意象。不把机器摘要当原文证据，也不要求每次把全书反复装入上下文。

### 术语、风格与审定译例

术语表是“候选提取 → 语境判断 → 初版裁定 → 随语境修订”，不是凭经验列几个词，也不是先冻结全书所有译法才能动笔。

1. **结构化取样**：提取英文及对应中文正文；代码、URL、导航和重复渲染内容不混入正文频率。表格、引用与脚注分别处理。
2. **发现候选**：按规模选择英文分词、词形还原、多词或名词短语，中文分词与领域词典；另查标题、索引、定义句及动词表达，保留低频重要概念，检查分词误差。
3. **复核计数**：记录频次与文件覆盖，说明原始词形、归并与别名重叠口径；核心词独立检索。标题线索单独使用，不混称正文频次。
4. **按义项裁定**：记录英文表达、首选中文、其他译法、适用义项、不得混同的概念、原文位置与证据、状态及裁定者。中文分词相近不证明英中等价，最高频译法不自动胜出。

风格表另外记录称呼、解释密度、缩写、标点、标题与图题形式、作者语气及保留的例外。技术书重点看概念和论证连续性；文学重视声音与叙述，不把所有章节磨成同一种中性文风。

只将经项目约定审核的片段收入可复用译例，并标明源版本、义项、审核者及审核方式。原始机翻、未经核对的旧译和模型自评不能自动成为规范；模型审核与人工审核不能混记。

优先用已有项目工具。缺工具时可按[通用脚本文档](reusable-scripts.md)使用 `corpus.py` 与 `terms.py`；专业表达规则显式配置，候选仍待审定。词表变动时记录影响范围并回查已完成章节，不机械统一不同义项。

## 3. 样章选路

新书、旧译质量未知或方法未定时，选择能覆盖一般正文、关键定义、复杂推理及图表／注释的代表性材料。样章用于明确质量标准和路线，不代表整书已经通过；既有可靠流程、续作和局部修正不强制重做比较。

| 输入状况 | 路线 | 边界 |
| --- | --- | --- |
| 没有译文 | 从原文初译 | 未经授权不调用额外模型或服务 |
| 旧译基本可靠 | 对照修订 | 保留正确、合适的表达 |
| 机翻可用但未审定 | 完整译后编辑 | 对照原文检查全部约定内容，不只修语病 |
| 持续误解、缺漏或逻辑失真 | 对相关段落重译 | 先诊断并保留旧稿；只审阅时提出建议，不实施 |

需要比较方法时，用相同材料、质量要求和审核口径比较可行路线；先看意义及覆盖，再看自然度、作者声音、总编辑／审校耗时和可核实成本，不只比生成速度或修改字数。缺少对照就不声称某路线最优；不固定换稿比例或用一项分数决定全书。

轻量处理只在用户明确接受参考用途时采用，不能因此把未完成审校的结果标为出版稿。局部路线可以不同，不要求全书一律重译或一律保留机器底稿。

## 4. 分批翻译与自检

以保留推理和引用关系为前提划分章节、小节或段落批次，不在条件、例子或图文关系中间机械截断。

每批交付给执行者的材料至少包含：源文版本与实际范围、必要上下文及定义原文、旧译和选定路线、当前术语／风格及审定译例、跨章回指、待决项、可写范围、交付形式和验证入口。材料只取相关部分，但保留原文回查路径；不只给词表和孤立句子。

1. **理解与起稿**：先核原文命题、定义和指代，使用选定路线产出或修订中文；不把机器底稿默认视为正确。
2. **意义与完整性自检**：对照源文查漏译、增译、逻辑、否定、情态、量词、比较基准、责任主体与技术概念；源文疑点另列，不能先把错误润色得更顺。
3. **中文表达修订**：解决实际阅读问题，保留正确译法和作者声音；不用改动数量证明工作量。
4. **改动回查**：回查实质改动对应的原文、术语及上下文，执行保护检查。风格改善不能抵消意义错误。

获准且适合并行时，按不重叠文件分配宿主原生 agents；先明确所有权，不能让多个 agent 同时修改同一文件。主负责人管理术语、风格、全局导航和整合。跨章争议提交证据，不让各章自行重定义共享概念，也不因可用 agents 而擅自调用独立模型 API。

## 5. 双语审校与中文通读

分别记录以下职责、实际执行者、输入版本、覆盖范围、发现与未决项，不能只写一个笼统的“已 QA”。

| 职责 | 检查对象 | 不能替代什么 |
| --- | --- | --- |
| 译者自检 | 自己稿件的意义、覆盖与保护范围 | 不算独立审校 |
| 双语审校 | 对照原文、译文及必要上下文检查意义与义项 | 不只看差异、抽样或译者解释 |
| 中文连续通读 | 顺着中文读完整约定范围，查连贯性、声音、重复与概念跳跃 | 不以逐句看英文替代中文阅读体验 |
| 最终格式校样 | 编辑及排版后的实际交付物 | 构建通过或 Markdown 源码检查不等于校样通过 |

整书目标要求完整覆盖时，双语审校不能仅审改过的句子；高风险内容加深复核，但风险抽样不能冒称全书审校。中文通读先按阅读顺序判断，再对疑点回查原文；通读产生的实质修改须重新核义。

独立双语审校由不同于该段译写者的审核者承担。纯 AI 流程可在获得授权后分离执行角色和上下文，但多个模型互评不等于专业人工审校，也不是错误相互独立的证明。没有独立审核者或专业人工参与时说明限制，不能为达到发布称谓而虚构角色。短文本可由同一执行者完成自检，不强制多角色协作。

## 6. 保护检查与最终校样

### 内容保护

- 区分可编辑中文、英文原文、代码、标识、公式、链接与图片目标、脚注、标题层级和章节顺序。纯保护文件用哈希，混合文件记录源位置及原片段；不能仅用“含汉字”或“不以 `>` 开头”判定整行可改。
- 保留已有段落排布和有版本绑定的对齐记录；行号只是辅助。未配对、重复、缺损及历史错字单列。
- 基线只读，不以刷新基线消除失败。批量工具先在代码、混排、引用、表格、嵌套链接和脚注样本上验证；未知结构保留并报告。
- `corpus.py snapshot/verify` 只是辅助，复杂 HTML、自定义 Markdown、混排英文精确边界和合法结构变化需项目适配。不能关闭整套保护校验来放行展示变化。

### 最终格式

不论是否改样式，都按约定交付格式核对完整内容、目录／书签、标题锚点、图题、表格、脚注往返、公式、代码、参考文献及跨章引用。HTML 检查真实阅读页，EPUB／PDF 检查对应阅读或排版结果；不为源 Markdown 交付强制建设额外阅读器。

同类结构要抽查渲染是否一致：同一列表的各项、同一层级的标题、同类注释和术语条目的外观应相同。术语单独成行的列表项要确认术语后有硬换行（行尾两个空格），否则说明文字会紧跟在术语后面。逐行审阅时登记为“已审阅、未改动”的行，也要和兄弟行比对行尾标记与缩进，文字正确不等于排版正确。项目可以用 Markdown 解析器找出术语后面是软换行的列表项，中英文两侧都查，再到真实阅读页确认。

中文版只删除或隐藏已有确认中文对应的英文，保留共享资源、中文引用与未译内容；简繁或其他派生版从审定主稿生成，检查地区术语例外，不另起一套漂移的译文。最终校样发现的实质文字修正仍回到原文与派生关系复核。

缺浏览器、阅读器或其他必需工具时列明未验证内容，不能写“校样通过”。基本校样不授权改 UI、加图、换框架或重写代码例子。只有用户另行要求教学图解或样式时，再使用 [reader-visualization.md](reader-visualization.md)；正文、原图复现、教学图解和语言改编各自标明来源与状态，不能彼此覆盖。

## 7. 疑问、定稿与变更

### 问题记录与裁定

沿用已有审核表，为实际问题记录源文位置和版本、原文／译文片段、类别、影响程度、理由、候选处理、裁定者与状态。可参考 MQM 的误译、漏译、增译、术语、语言规范、风格、排版等维度；这不构成标准认证或固定评分。

项目级来源标签区分 `translation_error`、`source_issue`、`teaching_adaptation`；它们不是 MQM 标准类别。原文疑点需证据并区分“疑似／已确认”。用户要求注释勘误时，正文保留原意，注释绑定原句并注明依据、不确定性，沿用既有样式。

影响主要概念、重要结论或跨章一致性的疑问列为阻塞对应范围定稿的待决项，集中给有裁定权的人处理；原文明显保留的歧义不能自行消除。不阻塞无关章节，也不把纯偏好问题反复交给用户。确认可以带注释交付的事项，记录决定与限制，不当作无条件解决。

### 定稿与停止条件

按任务约定核实源文覆盖、意义问题、术语及例外、各审核职责和最终校样；已知重要错误、未覆盖内容或必需验证缺失，不能被平均分抵消。参考稿可以按约定交付剩余限制，但不能静默换成交付等级更高的称谓。

正确合适的内容保留。约定检查已完成、无阻塞问题且没有可说明的改进时停止；不设无限“润色到最好”、固定轮数或改动配额。技能用例和脚本通过只证明对应检查，不能证明整书合格。

只把约定审核通过的片段回流为译例。定稿后源文、术语、中文、图解或代码改编有变化，定位受影响章节、引用和派生版本，撤销对应旧验收状态并重查；保留未变内容的有效证据，不全书无差别重做。最终报告实际完成范围、问题及裁定、审核者与方式、版本、验证命令和剩余限制；提交、推送、部署需对应授权。

## 8. 长任务检查点

沿用现有持久进度记录，至少保存任务约定、原始源文与工作区基线、语言资源版本、章节所有权、产物路径、分项审核状态、命令与结果、待决问题及下一步。不为短任务建立审计系统，也不自动提交大量临时材料。

- 状态区分准备、译写／编辑、自检、双语审校、中文通读、共享集成、格式校样和定稿；章节 agent 完成不代表整书完成。
- 临时目录可存截图和工具，但关键结论与恢复入口不能只在临时文件或聊天中。恢复时核对实际版本，旧证据缺版本绑定则标为历史。
- 核实当前预览服务和路由，不凭旧端口或截图认定页面可用；只补受影响检查，不重做已确认且未变的章节。
- 只读取相关摘要、结构化结果、必要原文与截图，不反复装入全量聊天和图片编码。缺证据就补查，不据此重启整项工作。
